## 前言

分布式拒绝服务攻击（DDoS）是互联网面临的最常见威胁之一。攻击者控制大量傀儡主机（僵尸网络）向目标发起海量请求，耗尽目标的带宽、连接数或应用资源，导致正常用户无法访问。本文从防御方视角梳理攻击类型与分层防御体系。

<!--more-->

## 攻击类型速览

| 类型 | 典型手法 | 消耗的资源 |
|---|---|---|
| 流量型（Volumetric） | UDP Flood、DNS/NTP/Memcached 反射放大 | 网络带宽 |
| 协议型（Protocol） | SYN Flood、ACK Flood、连接耗尽 | 连接表、协议栈 |
| 应用型（Application） | HTTP Flood、CC 攻击、慢速攻击（Slowloris） | 应用服务器 CPU/内存/线程 |

其中**反射放大攻击**值得特别注意：攻击者伪造受害者 IP 向开放的 UDP 服务（如 Memcached 11211 端口）发送小请求，服务将放大数十倍甚至数万倍的响应流量打向受害者。Memcached 反射的放大倍数曾达到 51000 倍，这也是公网 Memcached 必须绑定内网地址的原因。

## 分层防御体系

### 第一层：网络架构层

- **接入高防 IP / CDN**：将真实源站 IP 隐藏在清洗中心之后，攻击流量在云端清洗后再回源
- **Anycast 分散**：借助 CDN 的 Anycast 网络将攻击流量稀释到全球节点
- **源站 IP 保密**：源站只放行高防回源段 IP，历史 DNS 解析记录、证书透明度日志都可能泄露真实 IP，需一并排查

### 第二层：网络设备层

- 在上联路由器/防火墙上配置 **ACL、速率限制（Rate Limit）、SYN Cookie**
- 对 UDP 流量按业务必要性做端口级收敛
- 与运营商建立应急联动机制，必要时触发黑洞路由或近源清洗

### 第三层：主机层

- 调整内核参数缓解协议型攻击，例如：

```bash
# /etc/sysctl.conf 示例（仅示意，需结合业务压测调整）
net.ipv4.tcp_syncookies = 1        # 开启 SYN Cookie
net.ipv4.tcp_max_syn_backlog = 8192 # 增大半连接队列
net.ipv4.tcp_synack_retries = 2     # 减少 SYN-ACK 重传
net.core.somaxconn = 8192           # 增大全连接队列
```

### 第四层：应用层

- **WAF/CC 防护**：基于 IP 信誉、请求频率、人机验证（验证码/JS 挑战）识别恶意请求
- **限流与降级**：网关层配置令牌桶限流，核心接口做好熔断降级预案
- **静态化与缓存**：热点内容尽量交给 CDN/缓存层，减少穿透到应用

## 应急演练建议

1. 制定《DDoS 应急预案》，明确攻击识别、切换高防、业务降级、对外公告的决策链
2. 每年至少组织一次演练，验证切换高防的回源链路与证书配置
3. 与云厂商/清洗服务商签订 SLA，明确防护峰值带宽与响应时限

## 合规提示

根据《网络安全法》第二十一条和等级保护 2.0 的要求，网络运营者应当采取防范网络攻击、网络侵入的技术措施。对关键信息基础设施而言，DDoS 防护能力已是等保测评的常规检查项。
